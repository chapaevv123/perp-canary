## Owner flow

1. Run `npm run serve` locally. In **Execution Control**, choose BTC-PERP, BUY or SELL, limit price and BTC quantity. The browser requests only a read-only SDK/RPC preflight. It cannot sign or broadcast.
2. A `PREPARED` plan contains official `placeOrderFor` calldata, sampled market and position, gas/margin checks, risk caps, expiry, an intent ID and SHA-256 hash. Copy the hash. A `BLOCKED` plan cannot be executed. Plans expire in about two minutes.
3. Only if the owner separately decides to trade, run `npm run bot-execute -- execute <64-character-plan-hash>` in a local interactive terminal **before expiry**. The CLI verifies the plan chain, displays exact parameters, repeats live permission, collateral, gas, market, position, nonce and original calldata simulation checks, then requires typing `EXECUTE <same hash>`. It asks for the keystore password only in the local terminal. The password is not accepted by HTTP, browser or `.env`.
4. The CLI repeats chain 50383 and all live risk checks immediately before unlocking the local signer. It signs an exact legacy transaction and verifies its recovered signer, chain, target, calldata, zero value, gas and nonce. It sends once with RPC retries disabled. A durable intent reservation prevents a second attempt with the same intent ID. It never automatically retries an ambiguous broadcast.
5. On receipt, the app compares the raw transaction and receipt, `OrderPlaced`, `OrderFilled`, `PositionUpdated`, owner, BTC pool, side, quantity, limit price and position delta. `VERIFIED` requires full fill and position reconciliation. Partial or absent fills are `AMBER`; mismatches/reverts are `RED`. The SHA-256 forensic artifact includes the public raw evidence. `npm run verify` checks the old chains and new records.
6. If sending or receipt reads end in `UNKNOWN`, **do not execute again**. Inspect the recorded signed tx hash and run `npm run bot-execute -- reconcile <plan-hash> <tx-hash>` after the transaction is visible. Reconciliation is read-only.

Safety limits: Hideki 50383 only, Wallet 1 only, known BTC-PERP pool only, IOC `placeOrderFor` only, 100 USDso maximum order notional, 10 million maximum gas limit, 0.1 STT maximum estimated gas cost, 1% maximum mark move, and unchanged starting position. The exact same side/price/quantity/operator tuple has one lifetime intent ID, so a second identical plan requires a future reviewed reset mechanism; no automatic reset exists. No spot, transfer, withdrawal, token approval, unattended trading or remote signer endpoint is present. Gas and market execution can still change after the final preflight; IOC no-fill may revert.

The official [Link a Bot guide](https://app.testnet.dreamdex.io/docs/trading/common/link-a-bot) documents separate market and selector grants, bot-paid gas and owner-controlled revocation. The [perps developer guide](https://app.testnet.dreamdex.io/docs/developers/perps-testnet) and installed Markets SDK 0.32.1 support the read-only market, margin and grant checks and the confirmed `placeOrderFor` ABI. The [contract functions](https://app.testnet.dreamdex.io/docs/developers/contracts/functions) also document `cancelOrderFor` and `reduceOrderFor`, but this milestone leaves their execution **BLOCKED**: it does not yet independently verify a live order's owner, remaining quantity and permissible reduction from an on-chain order read. The dashboard only prepares placement.
