# M11 full product acceptance — Perp Canary

Date: 2026-10-28. M11 trading code: `7b17378`; acceptance baseline: `2c46bfc`; final control audit and legacy repair: `3f15e04`. Live URL: https://perp-canary.onrender.com/.

**Кратко для владельца:** ограничение 100 USDso убрано, настройка собственного лимита работает по кошельку, нерабочий выбор типа ордера заменен честным PostOnly. Локальные и браузерные проверки прошли. Публичный Render пока отдает файлы прежней версии; до подтверждения развертывания выпуск не завершен. Подписей и сделок M11 не было.

## Outcome and evidence

- **Inventory:** 102 initial DOM interactive controls; 101 locally exercised and passed, 1 external official documentation link left BLOCKED because its destination was not followed. Dynamic row controls (market favorites, Radar inspect, alert edit/pause/delete, Journal replay, order cancel) are covered separately by workflow tests. Eight existing control families were repaired or made truthful: order type, BUY, SELL, quantity, limit price, sizing calculation, apply sized quantity, and legacy diagnostics under CSP; two Trading Limits inputs were added. Confirmed remaining local control failures: 0. Local PASS does not certify live wallet execution or the outdated production build.
- **Tests:** ESLint, TypeScript typecheck, production build, 186/186 unit/integration and 23/23 local Chromium scenarios passed. Three gated live UI tests skipped and are not counted as passed. Browser tests using a deterministic EIP-1193 wallet or API fixtures are labeled mocked; no M11 live signature or transaction occurred.
- **Live data:** Pre-deploy read-only production browser smoke: HTTP 200, 21 markets, chain 50383, TRUSTED BTC and ETH pinned SDK/direct-RPC books, 3 SDK Journal rows, desktop/mobile without horizontal overflow or page errors. Separate live BNB snapshot also had a TRUSTED book. Live Radar scan of all 21 and live wallet account checks remain separately qualified.
- **Order types:** SDK 0.32.1 defines LIMIT, FOK, MARKET/IOC, POST_ONLY, but the verified browser preparation and validation support **PostOnly only**. Static “PostOnly (supported)” replaces the inert selector. BUY best bid and SELL best ask are noncrossing presets; opposite top is disabled. Side and market changes clear unsafe prices; market changes also clear quantity.
- **Trading limits:** no custom maximum by default. A positive USDso maximum can be enabled under Wallet & permissions, persisted by browser profile + connected EOA + account mode; it is checked in local preview and server preflight, and a change invalidates review. Quantity is never silently reduced. 500, 1,000 and 10,000 USDso are not rejected solely by Canary in deterministic tests; SDK placeable maximum, margin, market/grid, gas, permissions and protocol constraints still apply.
- **Security:** Public configuration exposes no secret; CSP restricts scripts/connect to self, HSTS is present, public API prepares unsigned calls and cannot broadcast user trades. Browser requests `eth_accounts`, explicit `eth_requestAccounts`, `eth_chainId`, explicit Hideki switch/add, and `eth_sendTransaction` only after review and an explicit confirmation click. No private-key request or external script was found. Render dashboard environment values were not accessible for independent inspection.
- **MetaMask:** Owner reports that connection now works without warning. On 2026-10-28 the official MetaMask phishing checker returned “This domain is not blocked! No problem here.” Headless Chromium has no owner's MetaMask extension, so current extension UI/permission state was not independently reproduced. Earlier warning is not treated as current confirmed block.
- **Remaining limits:** no M11 live wallet signing, direct EOA trade, cancellation or protective stop proof; the historical delegated BTC order and fill are independently evidenced in `docs/evidence/verified-delegated-btc-order.json`. Alerts run only while the tab is open; sizing stop is hypothetical; PnL/fees and Market/IOC execution are not claimed. Render Free can cold start.
- **Routes / architecture:** `/`, `/index.html` serve the public page; `/legacy` is available only in local owner mode. The local legacy diagnostics page had an actual CSP failure: its embedded script and styles were blocked. They are now served as first-party `/legacy.js` and `/legacy.css`; Chromium verifies both local navigation links and no CSP console errors. Public mode continues to deny the legacy routes. Read-only API families cover market snapshots/candles/trades, account/history/position, proof/replay, Radar sizing, health and public diagnostics. POST prepare routes construct unsigned direct/delegated orders, wallet actions, voucher and cancellation; they do not send transactions. Older owner CLI and bot routes remain gated by public-mode access rules. `render.yaml` uses the free Docker service and public unsigned API mode; no secret value is committed there.
- **Deployment at resumed audit:** `git ls-remote origin refs/heads/main` returned `2c46bfc99819d5b2b4da92f044f2dd6145ee2820`. Public Render returned HTTP 200 but `trading.js`, `terminal.js`, `preflight-compare.js`, `guard-v2.js`, `terminal.css`, and `/` all differed from local M11 checkout; the trading script and page lacked M11 markers. This is evidence that the latest M11 UI was not served at audit time. Render dashboard SHA is not publicly exposed.
