# Security model

The HTTP terminal binds to `127.0.0.1` and rejects cross-site requests. It does not load the keystore, accept passwords, expose a private key, sign, or broadcast. M5 adds read-only EOA/account/receipt routes and an unsigned direct-order prepare route. The browser can ask an injected EIP-1193 wallet to send only after a fresh Guard review and explicit click. The wallet, not the local server, signs and broadcasts. The legacy research page remains diagnostic.

The separate local CLI remains the only **verified executed** transaction path. An owner selects a fresh BUY PostOnly BTC-PERP price, gets a saved hash-bound plan, reviews it, runs the exact execution command, types `EXECUTE <64-character hash>`, and unlocks the encrypted local bot keystore with masked input. The CLI repeats a complete preflight immediately before signing and broadcast. Expired plans fail closed; plans are not repriced or extended.

Execution retains the existing 300-second plan and contract expiry, maximum 100 USDso notional, maximum 0.1 STT gas, maximum 1% mark deviation, TRUSTED SDK + direct RPC order book, margin and maximum placeable checks, grants, nonce, gas and simulation, exact calldata, sender, chain ID 50383, idempotency, and final preflight. This M4.2 work does not alter those gates.

The terminal reports `NOT_RUN` for nonce, expiry, deviation, gas estimate and order simulation before a specific plan is built. A balance or grant observation is not a passed execution gate. Browser copy controls never authorize a trade; the CLI asks for exact owner confirmation. A saved command is shown only while its plan is unexpired, and even then the CLI can block it for changing conditions.

M5.1 direct-wallet SELL PostOnly is offered with an explicit warning that it may add a short. BUY, SELL, bounded approval, deposit, withdrawal and cancellation require separate reviews and wallet confirmations; no user-wallet receipt has verified these routes yet. IOC, market orders and guaranteed position close are unavailable. `reduceOrderFor` reduces a resting order, not a perp position. Do not claim CLOSE_POSITION support without a separately validated close path. See [M5 capability matrix](M5_TRADING_CAPABILITY_MATRIX.md).
