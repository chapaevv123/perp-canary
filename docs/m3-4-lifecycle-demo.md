# M3.4 — BTC-PERP lifecycle and demo, 2026-10-27

## Contract semantics and scope

The [official functions reference](https://app.testnet.dreamdex.io/docs/developers/contracts/functions) confirms `placeOrderFor(owner,…)`, `cancelOrderFor(owner,orderId)` and `reduceOrderFor(owner,orderId,newQuantityRemaining)`. The last function reduces **a resting order's remaining quantity**. It does not reduce an open perp position. The installed Markets SDK 0.32.1 confirms the selectors `0x80054449`, `0xe37b444b`, `0x364c2587`, the on-chain order reads and `OrderCancelled` / `OrderReduced` event ABI. No verified operator-accessible position close primitive with atomic reduce-only semantics was found. A manually built opposite-side `placeOrderFor` could enlarge or reverse a position if it changed between preflight and inclusion. Therefore **position CLOSE and partial position REDUCE remain BLOCKED**; the existing Wallet 1 long is untouched.

## Owner-controlled lifecycle

1. **LIVE READ-ONLY:** Start `npm run serve`; Bot Connection reads effective selector grants. Execution Control reads the Wallet 1 BTC-PERP position, mark, price PnL, liquidation price and the pool's open orders directly through Markets SDK chain reads. Values show their block provenance. If a field cannot be read, it shows UNKNOWN.
2. **PLACE:** Choose side, limit and quantity, then `Plan and simulate`. The M3.3 placement path writes a SHA-256 immutable plan. It remains blocked if gas, margin, market, permission, IOC execution or any other hard gate fails. It never sends from the browser.
3. **CANCEL / REDUCE RESTING ORDER:** Select a LIVE order ID. The app requires the on-chain open-order list and an independent pinned `getOrderOnchain` read to agree on ID, owner, pool, side, price, full and remaining quantity. For `REDUCE_ORDER`, enter the desired new remaining BTC amount; it must be smaller, lot-aligned, at least minimum size and not expired. The app reads the exact independent grant, simulates the official calldata and saves a hashed plan. Missing, filled, cancelled, foreign or stale orders produce no executable plan.
4. **OWNER APPROVAL:** Only after a separate decision, use `npm run bot-execute -- execute <plan-hash>` in the local terminal before expiry. CANCEL / REDUCE_ORDER require the exact phrase `EXECUTE <operation> <hash>`; PLACE retains `EXECUTE <hash>`. The CLI repeats on-chain ownership, order state, permission, gas, chain, nonce and exact calldata simulation before prompting for the encrypted keystore password. It rechecks immediately before signing. The shared M3.3 signer, signed-field verification, atomic intent lock and one-shot broadcast are reused; no HTTP signer or automatic sequence exists.
5. **VERIFY:** Transaction and receipt hashes, chain, sender, pool and calldata are checked. PLACE requires `OrderPlaced`, fill and position evidence. CANCEL requires the documented `OrderCancelled(orderId)` event and an absent active order after receipt. REDUCE_ORDER requires `OrderReduced(orderId,newQuantity)`, the exact new on-chain remainder and unchanged position; ambiguous state is AMBER or RED. Every forensic artifact contains raw public receipt/effects plus SHA-256 linkage to the immutable plan. A broadcast timeout is UNKNOWN and requires manual reconciliation, never a retry.
