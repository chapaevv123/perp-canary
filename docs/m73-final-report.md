# Отчёт M7.2 + M7.3 — 28 октября 2026

## Восстановление и причины сбоя

Работа продолжена от локального коммита M7.1 `8278be40d94615a3700797cfc09b8f3a5bd91c3c`. Сохранены код M7, исправление Firefox localhost, подтверждённая история делегированного BTC ордера и нетронутая папка `design/`.

Наблюдавшийся `genesis check failed` был следствием отсутствия исходящего сетевого доступа у процесса Node, запущенного в ограниченном окружении: независимые HTTP RPC и GraphQL пробы возвращали `EACCES`, а WebSocket не устанавливался. SDK использует WebSocket для проверки цепи, поэтому отсутствие соединения проявлялось как ошибка genesis. Проверка **не отключена**. `indexer fetch failed` имел тот же корень — запрет исходящего HTTPS для этого процесса. После перезапуска приложения с сетевым доступом все три независимые пробы и браузерный терминал заработали. Это установленная причина воспроизведённого локального отказа; при другом окружении диагностический блок теперь показывает независимое состояние источников.

Рабочие официальные адреса для Hideki 50383: HTTP RPC `https://api.hideki2.infra.testnet.somnia.network`, WebSocket `wss://api.hideki2.infra.testnet.somnia.network/ws`, indexer `https://hideki-dev.smk.somnia.host/v1/graphql`. Версия SDK `@somnia-chain/markets-sdk@0.32.1`. Сверено с [документацией dreamDEX](https://app.testnet.dreamdex.io/docs/developers/perps-testnet) и живыми read-only запросами. При проверке `/api/v1/health/sources` все четыре источника — RPC, WebSocket, indexer и BTC pool — вернули `HEALTHY`.

Полный Chromium прогон также обнаружил рекурсивный `WebSocket.close()` в обработчике ошибки нового health probe. При недоступном WebSocket он мог завершить Node процесс переполнением стека. Вызов удалён; повторный прогон всех UI тестов прошёл.

## Что реализовано

Реестр загружается динамически из SDK и сверяется с фабрикой и параметрами пулов. Найден **21 PERP рынок**: ZRO, LIT, VVV, 1000PEPE, PUMP, ZEC, TAO, WLD, NEAR, XLM, AVAX, LINK, SUI, ADA, BNB, DOGE, XRP, HYPE, SOL, ETH и BTC (каждый с суффиксом `-PERP`). Все 21 на момент проверки имели статус активного пула `TRADEABLE` и доступны для просмотра. Статус пула не даёт торговое право кошельку: оно проверяется отдельно для каждого рынка, счёта и grant перед review. Spot рынки не представлены как PERP. Неизвестные 24-часовые метрики обозначены `Unavailable`.

Терминал теперь имеет большой свечной график, независимый стакан и торговый билет в одной строке на широком экране; рабочую область счёта с шестью вкладками; адаптивный планшетный и мобильный вид; более крупные шрифты; скрываемые технические детали. Селектор поддерживает поиск, избранное, недавние рынки и клавиатуру. Смена рынка очищает старые значения до нового чтения и отбрасывает запоздавшие ответы. График использует только реальные fill-derived OHLCV из indexer, показывает время, цену, объём и OHLC при наведении. Стакан сверяет SDK и прямые on-chain уровни на одном блоке.

Проверенный тип нового ордера — только PostOnly limit. Кнопка Review выполняет свежие проверки рынка, разрешений, маржи, газа и симуляцию, не отправляя транзакцию. Canary Guard V2 объясняет `SAFE / CAUTION / BLOCKED / UNAVAILABLE` и повторно проверяется перед запросом кошелька. Нельзя обещать безопасный delegated reduce-only close: подтверждённого пути нет. При потере источника зависимые действия блокируются; HTTP RPC, WebSocket, indexer и pool диагностируются отдельно. После временного сбоя индексатора ранее подтверждённый реестр можно читать в режиме read-only, но новый ордер требует свежего подтверждения.

Позиция Wallet 1 читается на счёте владельца, а не на пустом margin счёте оператора. Живой снимок BTC: `LONG 0.05429 BTC`, вход около `80045.8023 USDso`, on-chain pinned block зафиксирован в браузерном отчёте. Отображаемые числа округлены для чтения; исходные SDK значения не меняются. Нереализованный cumulative realized PnL явно недоступен. Ликвидационная цена названа оценочным ориентиром SDK, сценарий — оценкой изменения цены, а не обещанием исполнения.

Execution Replay сохраняет факт исторического ордера `14978756187852164141712`, размещение `0xb542d3a603b33a598f8dab8d2e4f38c8b7ee163bfbd169dd32acc9429d35d28f`, исполнение `0x1b7e19bb1afbf14ed21e74da7cf667ccb17c40ec310698293dbd6e4c343f65d4` и только **0.00013 BTC** прироста, относящегося к Canary. Предшествующая позиция Wallet 1 не приписана этой сделке. Историческая проверка Guard не придумана.

## Реальная браузерная проверка

Локальный `GET /` вернул HTML с HTTP 200. Chromium подключался к действующему локальному серверу без моков рыночных API. BTC: mark около `81,062.52`, bid `81,255.90`, ask `81,266.80`, **120 реальных свечей 5m**. ETH: mark около `2,361.86`, bid `2,362.25`, ask `2,362.60`, также **120 реальных свечей 5m**. Это значения конкретного read-only прогона, не обещание текущей котировки. Оба стакана были `TRUSTED`; RPC, WebSocket, indexer и pool показывали live. Инъекция браузерного EIP-1193 кошелька служила только для `eth_accounts` и `eth_chainId`, все методы подписи/отправки были запрещены. Позиция владельца BTC загрузилась в Chromium; ошибок страницы не было.

Сценарии деградации проверены отдельно с явно мокированным отказом транспорта: UI сообщает об отключённом WebSocket, не выдаёт старый стакан за свежий и отключает зависимые действия. Макеты тестов не названы живым исполнением. ## Внешние ограничения и действия владельца

Для запуска на своём компьютере: `npm.cmd run serve`, затем `http://127.0.0.1:8787/`. Требуется доступ процесса Node к трём адресам Hideki по HTTPS/WSS. Если сеть блокирует их, терминал покажет отдельные состояния источников и не разрешит непроверенную торговлю.

Перед публичным запуском нужны домен/VPS, HTTPS конфигурация и разрешение владельца на деплой, затем реальный public-mode smoke. Отправка в GitHub и DoraHacks также требуют отдельного разрешения владельца. Дедлайн и whitelist надо подтвердить в официальном портале; автоматическая проверка портала ранее не дала достоверного времени закрытия. Новых ордеров, подписей, закрытий позиции и on-chain транзакций в M7.3 не выполнялось.

Локальный M7.3 commit: см. `git log -1 --oneline` после создания коммита; это поле умышленно не фиксирует меняющийся хеш самого файла.
