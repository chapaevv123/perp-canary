# M3.3.1 — IOC preflight root cause, 2026-10-27

The saved, verified plan `8b5d51f8609d79c527de185294bdbef1baa4e232d5728a3405629596b721cfd0` requested BTC-PERP BUY 0.0002 BTC at 79990 USDso on Hideki block 34030745. Its `transaction` is null because `eth_estimateGas` failed. The RPC response was previously discarded, so the UI showed five secondary gate failures beside a generic simulation failure.

Read-only reproduction used the documented `placeOrderFor` selector `0x80054449`, bot as `from`, Wallet 1 as `owner`, and the known BTC-PERP pool as `to`. Both `eth_call` and `eth_estimateGas` returned RPC code 3 with revert data `0xd48c4403`. The [official contract error table](https://app.testnet.dreamdex.io/docs/developers/contracts/errors) identifies this as `ImmediateOrCancelNoFill()`. The installed Markets SDK's on-chain top-of-book read at the original block showed best ask **80024.9**, above the BUY limit **79990**. Thus this IOC order could not fill. At fresh block 34034090 the best ask was **80053** and the same read-only preflight remained `BLOCKED` with the same decoded revert.

Chain ID was 50383; the bot had 5 STT; Wallet 1 had 1000 USDso unlocked margin; `placeOrderFor` effective permission and SDK market checks were `SUPPORTED`; margin preview passed. The BTC price and quantity met market precision checks. `chain`, `gas`, `fresh`, and `targetAndCalldata` gates failed only because the rejected simulation clears the unsigned transaction and gas estimate. Their safety conditions remain unchanged. The contract revert is the primary error, rather than a network, ABI, gas, permission or collateral failure.

The safe fix preserves the failed estimate and `BLOCKED` status. It extracts the raw RPC revert selector from viem's cause chain, reads the pinned on-chain best ask where available, and shows **PRIMARY ERROR**, **BLOCKED DEPENDENCIES**, RPC/contract details, and the next action in Execution Control. No automatic repricing, fallback RPC, simulation bypass or transaction was added. The owner can review current ask and their acceptable slippage, then manually choose a new limit and make a fresh read-only plan. An IOC book can move again before inclusion, so even a successful estimate is not an execution guarantee.
